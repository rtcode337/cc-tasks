# cc-tasks 詳細設計

- 最終更新: 2026-07-29
- ステータス: **現行実装の正**。実装を変えたらこのファイルも同じコミットで直す

アプリの目的:

- **Claude Code への依頼の思いつきをメモで残す** —— 出先でスマホ(PWA)から放り込み、腰を据えて作業できるときに消化する
- **Claude Code に守らせたいルールを 1 箇所で管理する** —— 全環境に効かせたい決まりごとを 1 本の Markdown に連結して取り出す

利用者は本人 1 名のみ(Google OAuth、許可メール 1 件固定)。

---

## 1. アーキテクチャ

```
[スマホ/ブラウザ PWA]
   Google OAuth セッション
            |
   リバースプロキシ (TLS 終端)
            |
  Spring Boot (単一コンテナ)
    /         → Vue SPA (static)
    /api/**   → REST API (要セッション)
    SQLite: /data/cctasks.db
```

| レイヤ | 技術 |
|---|---|
| バックエンド | Java 25 / Spring Boot 4.1 / Spring Data JDBC / SQLite |
| フロントエンド | Vue 3 / Vite / TypeScript / Pinia / vite-plugin-pwa |
| 配信 | マルチステージ Docker ビルドで単一コンテナ。HTTPS 終端は手前のリバースプロキシの責務 |

- フロントのビルド成果物を Spring の static に同梱するため、本番はオリジン 1 個
- ロジックは `ProjectService` / `TaskService` / `RuleService` に置き、コントローラは薄く保つ
- PWA のキャッシュはアプリシェルのみ。`/api/**` は network-only(オフライン編集はスコープ外)
- 管理系エンドポイント(Actuator 等)は持たない

## 2. データモデル

DDL の正は [backend/src/main/resources/schema.sql](../backend/src/main/resources/schema.sql)。
起動のたびに `CREATE TABLE IF NOT EXISTS` で流すため新規 DB にしか効かず、
既存 DB への列の追加・削除は `SchemaMigrations`(起動時の冪等な ALTER)が担う。

**列ごとの定義・ER 図・クラス図は [データベース定義.md](データベース定義.md) にある**
(ここは概要にとどめる)。

| テーブル | 中身 | ポイント |
|---|---|---|
| `projects` | タスクの入れ物(リポジトリ 1 つに対応する想定) | `repo_url` は複数可・改行区切り。`archived` 0/1。`sort_order` で手動並び替え |
| `tasks` | Claude Code に依頼したいこと | 持つのは **title だけ**(背景・受け入れ条件などの列は廃止)。`project_id` は nullable(未分類)。`status` は `todo`(未着手)/ `in_progress`(着手中)/ `done`(完了)の 3 値。着手中を許さない CHECK の時期に作られた DB は `SchemaMigrations` がテーブルを作り直す。`sort_order` はプロジェクト内でだけ効く(0 = 未並び替えで先頭) |
| `rules` | 全環境に効かせたい決まりごと(Markdown) | `enabled` 0/1(無効は連結に含めない)。`sort_order` がそのまま連結順 |
| `settings` | 汎用キーバリュー(行が無い = 未設定) | 現状は規約リポジトリ `rules_repo_url` だけ |

- 日時は ISO 8601 の TEXT(UTC)
- タスクの状態遷移に制約は設けない(手戻り・中止を許容)
- タスク削除は物理削除。プロジェクト削除は紐づくタスクを完了分ごと同一トランザクションで消す

## 3. 認証・セキュリティ

- Spring Security の `oauth2Login`(Google)。ログイン成功後にメールを環境変数
  `ALLOWED_EMAIL` と照合し、不一致は即拒否(ユーザーテーブルは作らない)。
  **`email_verified` が真であることも確認する** —— メールだけで人を同定する設計なので、
  未検証のアドレスを受け入れると「他人のアドレスを名乗るアカウント」で入れてしまう
- セッションはサーバーサイド(Cookie は `SameSite=Lax`, `HttpOnly`。`Secure` は
  リクエストのスキームから自動判定)。ディスク永続化で再起動しても再ログイン不要。timeout 30d
- `/api/**` はセッション必須。未認証は 401、CSRF トークン無しの更新系は 403
- ログイン試行はレート制限(20 回/分で 429)。**キーは `request.getRemoteAddr()`**
  (`X-Forwarded-For` を自分で読まない)。ヘッダは攻撃者が自由に付けられ、プロキシは
  消さずに後ろへ追記するため、先頭を採ると毎リクエスト別バケットになって制限が丸ごと
  無効化される。`forward-headers-strategy: native` の RemoteIpValve が信頼できる
  プロキシを判定して入れた値を使う
- **リダイレクト URI をリクエストヘッダから組み立てるのは `ALLOWED_REDIRECT_HOSTS`
  に載っているホストだけ**(Host ヘッダ注入対策)。`PUBLIC_BASE_URL` 設定時はそちらが
  優先され、どちらも未設定なら自動導出は行わず `{baseUrl}` 展開に委ねる(起動時に警告)
- `dev` プロファイルは認証を通さない(開発専用。本番では絶対に有効化しない)

## 4. REST API

すべて `/api` 配下、JSON、要セッション。エラーは `{"error":{"code":"...","message":"..."}}`。

| メソッド | パス | 説明 |
|---|---|---|
| GET | `/api/me` | ログイン中ユーザー |
| GET | `/api/projects` | プロジェクト一覧 (`?archived=false` が既定、`?archived=` で全件) |
| POST | `/api/projects` | 作成 |
| PATCH | `/api/projects/{id}` | 更新 (name, repoUrls, description, archived)。repoUrls は配列(空配列で全消し)。`archived:true` は未完了が 0 件のときだけ通る(残っていれば 400) |
| DELETE | `/api/projects/{id}` | 削除。**アーカイブ済みのときだけ**通る(未アーカイブなら 400)。紐づくタスクも完了分ごと消える |
| PUT | `/api/projects/order` | 並び替え。全プロジェクトの id を望む順で送る (`{"ids":[...]}`)。並び替え後の全件を返す |
| GET | `/api/tasks` | 一覧 (`?projectId=&status=`)。`?done=false` で未完了(done 以外)一覧 |
| POST | `/api/tasks` | 作成 (projectId は任意) |
| PUT | `/api/tasks/order` | プロジェクト内の並び替え。`{"projectId":1,"ids":[...]}` を望む順で送る(未紐づけは `projectId:null`)。画面に出ている分だけの部分集合でよいが、別プロジェクトのタスクを混ぜると 400 |
| GET | `/api/tasks/{id}` | 詳細 (プロジェクト名込み) |
| PATCH | `/api/tasks/{id}` | 更新 (projectId, title, status)。null のフィールドは変更しない。**`projectId:0` は「紐づけを外す」**(未分類に戻す) |
| DELETE | `/api/tasks/{id}` | 削除 |
| GET | `/api/rules` | ルール一覧 (表示順。無効なものも含む) |
| GET | `/api/rules/combined` | 有効なルールを表示順に連結した Markdown (`{"markdown":"..."}`)。先頭に適用範囲の前置きと「規約リポジトリの扱い」ルールが付く |
| POST | `/api/rules` | 作成 (title, body, enabled) |
| PATCH | `/api/rules/{id}` | 更新 (null のフィールドは変更しない) |
| DELETE | `/api/rules/{id}` | 削除 |
| PUT | `/api/rules/order` | 並び替え。全ルールの id を望む順で送る。並び順がそのまま連結順になる |
| GET | `/api/rules/settings` | ルール画面の設定 (`{"rulesRepoUrl":"..."}`。未設定なら null) |
| PATCH | `/api/rules/settings` | 規約リポジトリの更新。null は変更しない、空文字で解除 |

- JSON は camelCase。リクエストは snake_case (`project_id` 等) でも受け付ける
- 更新系は `X-XSRF-TOKEN` ヘッダが必要(Cookie の `XSRF-TOKEN` をそのまま返す)
- PATCH は「null のフィールドは変更しない」部分更新。空文字は「消す」。
  数値の id はこれだと「消す」を表せないので、`PATCH /api/tasks/{id}` の `projectId` だけは
  `0` を「紐づけを外す」の意味に使う(id は 1 から振られるので衝突しない)

## 5. 画面構成

| 画面 | パス | 役割 |
|---|---|---|
| トップ | `/` | タスク入力 + **未完了**一覧。プロジェクトの作成・編集・並び替えもここで完結 |
| 完了したタスク | `/done` | 完了したタスクの一覧。未着手に戻せる |
| アーカイブしたプロジェクト | `/archived` | アーカイブ済みプロジェクトの一覧。戻す・削除する |
| ルール | `/rules` | 全 Claude Code 環境に効かせたい決まりごとの管理 |
| ログイン | — | 「Google でログイン」のみ(dev プロファイルでは不要) |

ヘッダは **トップ / ルール / ログアウト / テーマ切替(明暗)**。
タスクの一覧・詳細・編集の専用画面は持たない(編集はモーダル)。
プロジェクトの専用画面も持たない。廃止した旧パスへの直リンクはワイルドカードでトップに流れる。

## 6. トップ(未完了)

上から順に:

1. **タスク入力**(数行のテキストエリア)+ プロジェクト選択(任意)+ 保存
   —— 選択肢は**プロジェクトの並び順で、「プロジェクトなし」は末尾**。
   既定は**先頭のプロジェクト**(初回の読み込み時に決める。プロジェクトが 0 件なら「なし」)
2. 「未完了」見出し(右端に **バックアップ / ＋ プロジェクト**)
3. **未完了一覧**: プロジェクトごとの折りたたみグループ

一覧の決まり:

- 既定は**折りたたみ**。開閉状態はブラウザに保存する
- グループの並びは**プロジェクトの並び順**
- **プロジェクト未設定のタスクは「未分類」として一番下**。トップでは**該当が 0 件でも出す**
  —— 放り込み先であり、ドラッグで紐づけを外す落とし先でもあるため
- **タスクが 0 件のプロジェクトも並べる**(そこへ放り込む導線になるため)。
  例外はアーカイブ済みで、こちらはトップに出さない
- 一覧の一番下の左に「完了したタスク →」、右に「アーカイブしたプロジェクト →」
- 見出しの**バックアップ**は未完了タスクの持ち出しと復元(→ [README](../README.md#タスクのバックアップ))。
  **書き出しと読み込みは 1 つのモーダルにタブで収める**(既定は書き出し)。
  モーダル右上は**閉じる(×)**。コピーは本文の**枠の中の右上に重ね**る。
  どちらのタブも**見出しの行**を持ち(書き出す内容 / 書き出した内容)、その右端に
  ファイルのボタン(**アイコンにせず文言のまま**)を置く。
  **決まりごとの説明は見出しのすぐ右の「?」を押したときだけチップで出す** ——
  常に出しておくと、毎回読む必要のない文章が本文の場所を取るため

## 7. 完了したタスク(`/done`)

- 導線はトップ左下のリンクのみ。**トップへ戻るリンクは一覧の左下**(来たときと同じ位置)
- **見え方はトップの未完了一覧と同じ**(プロジェクトごとに折りたたみ、未分類は末尾)。
  ただし並び替えとプロジェクト編集は持たない
- 完了タスクを持つプロジェクトだけ出す(「放り込み先」の意味が無いため 0 件は出さない)。
  未分類グループも 0 件なら出さない —— トップと違うのはここだけ
- カードの「未着手に戻す」でトップへ戻る

## 8. アーカイブしたプロジェクト(`/archived`)

- 導線はトップ右下のリンクのみ。**アーカイブを戻せる唯一の口**。
  **トップへ戻るリンクは一覧の左下**(完了したタスクと同じ)
- 見え方はトップと同じ。ここからアーカイブ解除と削除を行う

## 9. ルール(`/rules`)

- 全 Claude Code 環境に効かせたい決まりごとを Markdown で何本でも持つ
- 「まとめて表示」で、有効なルールを**表示順に 1 本へ連結**して表示・コピーできる
  (長押しドラッグの並び順がそのまま連結順)。モーダルは Markdown を素のまま `<pre>` で出し、
  上に貼り先の説明を添える。右上はコピーと**ファイルに書き出す**の 2 つ(書き出しが左)
- 「取り込み」は連結の逆。貼り付けのほか、右上のボタンで**ファイルからも読み込める**
  (どちらも入力欄に入るだけで、取り込みは確認してから)
- 連結は**サーバー側**(`GET /api/rules/combined`)で行う。貼り付ける本文と API の返す本文を
  常に一致させるため
- 連結の**先頭には 2 つが自動で付く**(ルールとして登録はしない):
  適用範囲の前置き(「特定リポジトリの説明ではなく、作業対象のすべてのリポジトリに効く共通ルール」)と、
  「規約リポジトリ自体は配布専用なので自動更新しない」というルール
- 無効にしたルールは連結に含めない(消さずに一時的に外せる)
- 一覧の下で **規約リポジトリ**(GitHub の `owner/repo` か URL)を設定できる。
  設定すると ✳ ハンドオフの `repositories` に**常に**付与され、そのリポジトリの
  ルート直下 `CLAUDE.md` が読み込まれる。空にして保存すると解除
- 貼り先と運用は [README](../README.md#ルールを-claude-code-に効かせる) 参照

## 10. タスクの操作

### 状態

**未着手 / 着手中 / 完了 の 3 つ**。着手中は「Claude Code に依頼はしたが
動作確認が済んでおらず閉じられない」を表す。トップの一覧に出るのは
未完了(done 以外)= 未着手 + 着手中。
切り替えは**カードのボタンからだけ**行う(未完了一覧では「着手」「完了」、
着手中のタスクは「着手中」を押すと未着手に戻る、完了一覧では「未着手に戻す」)。
編集モーダルに状態の選択は置かない —— 同じことが 2 箇所からできると、どちらが正か分からなくなるため。

### カード

| 場所 | 操作 |
|---|---|
| 本文 | 押すと**編集モーダル**が開く |
| 右上 📋 | 本文をクリップボードへコピー |
| 📋 の隣 ✳ | **Claude Code へのハンドオフ**(§13) |
| 右下 | 着手(着手中なら色付きの「着手中」。押すと未着手に戻る)/ 完了。完了一覧では「未着手に戻す」 |

### 編集モーダル

- 編集できるのは **タスク内容 / プロジェクト** のみ
- プロジェクトで「プロジェクトなし」(選択肢の末尾)を選べば紐づけを外せる
- **物理削除はここから**。誤タップを避けるため一覧には置かない

### プロジェクト紐づけ

任意。未紐づけのまま放り込み、あとから紐づけられる。

## 11. プロジェクトの作成・編集・アーカイブ・削除

**すべてトップで完結する**(専用画面は持たない)。

| 操作 | 場所 | 条件 |
|---|---|---|
| 新規 | 「未完了」見出しの右端の「＋ プロジェクト」 | — |
| 編集 | 各グループ見出しの右端の「編集」 | — |
| アーカイブ | 編集モーダルの右上のボタン | **未完了が 0 件のときだけ** |
| アーカイブから戻す | 同上(アーカイブ済みなら表示が変わる) | 無条件 |
| 削除 | 同じ行の右端の「削除」 | **アーカイブ済みのときだけ** |

- アーカイブのボタンを押すと、**入力中の内容ごと**保存して閉じる(編集を捨てさせない)
- アーカイブを未完了 0 件に限るのは、片付いていないタスクごとトップから消えると
  放り込んだものを取りこぼすため。UI で disabled にするだけでなくサーバー側でも弾く
- 削除は**完了したものを含め、紐づくタスクも一緒に消える(戻せない)**。
  アーカイブ自体が「未完了 0 件」を条件にしているので、片付いたことを確かめる一段を必ず通る

## 12. 並び替えとドラッグ移動

### 並び替え

行のどこでも **長押し(ロングタップ)してからドラッグ**(マウス・タッチ両対応)。
掴み代(☰)は置かない —— 画面が狭く、カード幅を削りたくないため。

| 掴むもの | 変わる並び |
|---|---|
| グループ見出し | プロジェクトの並び |
| カード | そのプロジェクト内のタスクの並び |

- 長押しの前に指を動かせば普通のスクロールのまま(一覧の操作を邪魔しない)
- タスクの手動並び順は**プロジェクト内でだけ**効く。プロジェクトをまたぐ並びは作成日時降順のまま
- 新しく放り込んだタスクはグループの**先頭**に積まれる

### プロジェクト間の移動

カードを**別のプロジェクトのグループまで運んで離すと、そのプロジェクトへ移る**。

- 受け皿になっているグループには枠が付く
- **落とした位置にそのまま入る**
- 「未分類」のグループへ運べば紐づけを外せる。トップでは未分類を 0 件でも出すので、
  **落とす先は常にある**(編集モーダルで「プロジェクトなし」を選んでも同じ)

## 13. Claude Code へのハンドオフ(✳)

タスク内容をプリフィルした `https://claude.ai/code?prompt=…&repositories=…` を新規タブで開く。

- プロンプトは**タスク内容そのもの**。タスク番号は付けない(MCP 廃止後は
  Claude Code 側から cc-tasks を参照できないため)。規約リポジトリが設定されていれば、
  先頭に「まず規約リポジトリの CLAUDE.md(共通ルール)に従う」の一言が付く
- `repositories` には、プロジェクトのリポジトリ URL のうち **GitHub のものだけ**を
  `owner/repo` に変換して渡す。ルール画面で **規約リポジトリ**を設定していれば、
  それも常に加わる(重複すれば足さない)
- 送信はプリフィルのみ。実行開始はその場でワンタップ

### スマホ(iOS)の注意

初期状態ではユニバーサルリンクで Claude アプリが開き、**アプリはクエリのプリフィルを
引き継がないため内容が失われる**(空タブ + JS 遷移、中継ページ経由の JS 遷移のどちらでも回避できなかった)。

- **一度リンクを長押しして「Safari で開く」を選ぶ**と iOS がそれを覚えてブラウザで開くようになり、
  以後はプリフィルが効く
- ホーム画面追加(PWA)の場合はアプリ内ブラウザだと claude.ai のログインセッションを共有しないため、
  `x-safari-` スキームで Safari 本体を開いている

### 将来構想: iOS 依存を減らす

スマホでのプリフィルは上記のとおり iOS の挙動頼みで成立している。
Claude モバイルアプリがユニバーサルリンクのクエリ(`prompt` / `repositories`)を
引き継ぐようになれば、これらの回避は不要になり素の直リンクに戻せる。

## 14. 全画面共通

- **下に引っ張って再読み込み**(PWA にはリロード手段が無いため)。
  トップ・完了・ルール・アーカイブ一覧では**データだけ**を取り直し、
  それ以外の画面ではページ全体をリロードする
- **通信中は画面全体を半透明の白いオーバーレイで覆う**(スピナー + 「通信中…」。操作もブロック)。
  表示は 0.3 秒待ち、すぐ終わる通信では出さない(保存のたびに画面が点滅するのを防ぐ)。
  進行中のリクエスト数は `lib/network.ts` で数え、API クライアントが開始・終了を報告する
- **通信失敗はダイアログを 1 回出し、OK でログイン画面へ戻す**。
  「通信失敗」= リクエストが届かない/応答が返らないこと:fetch の失敗、タイムアウト(30 秒。
  低速なディスクが眠った環境の初回アクセスを考慮して短くしすぎない)、
  リバースプロキシのゲートウェイエラー(502/503/504)。
  バックエンド自身が返す 4xx/5xx の API エラーは従来どおり各画面のバナーで出す
- **認証確認(`GET /api/me`)が済むまで画面を描画しない**(「読み込み中…」のみ)。
  未認証のまま描いてよいのはログイン画面だけ
- **フッター(横線の下)にビルド番号**(JST 日付 + コミット短縮ハッシュ、例 `20260729-a8f447f`)。
  SW の旧キャッシュや未更新のイメージを見ていないかの切り分け用。
  ビルド時に注入する(Docker ビルドへは CI がコミット SHA を build-arg で渡す)
- モバイルファースト。入力の摩擦を最小にする(トップで「一言書いて即保存」ができること)
- テーマは明暗の切替をヘッダに持つ
- UI 文言はすべて日本語
