# cc-tasks 画面・操作仕様(現行)

- 最終更新: 2026-07-28
- ステータス: **現行実装の正**(画面・操作まわりに限る)

[仕様書_v0.1.md](仕様書_v0.1.md) の §8「フロントエンド(PWA)仕様」は、専用画面の廃止・
状態の 2 値化・ルール機能の追加などで実態と離れたため、**画面と操作についてはこのドキュメントが正**。
v0.1 は当初の設計意図の記録として残す。実装上の理由・ハマりどころ(長押しドラッグの実装、

## 1. 画面構成

| 画面 | パス | 役割 |
|---|---|---|
| トップ | `/` | タスク入力 + **未完了**一覧。プロジェクトの作成・編集・並び替えもここで完結 |
| 完了したタスク | `/done` | 完了したタスクの一覧。未完了に戻せる |
| アーカイブしたプロジェクト | `/archived` | アーカイブ済みプロジェクトの一覧。戻す・削除する |
| ルール | `/rules` | 全 Claude Code 環境に効かせたい決まりごとの管理 |
| ログイン | — | 「Google でログイン」のみ(dev プロファイルでは不要) |

ヘッダは **トップ / ルール / ログアウト / テーマ切替(明暗)**。
タスクの一覧・詳細・編集の専用画面は持たない(編集はモーダル)。
プロジェクトの専用画面も持たない。

## 2. トップ(未完了)

上から順に:

1. **タスク入力**(数行のテキストエリア)+ プロジェクト選択(任意)+ 保存
2. 「未完了」見出し(右端に **＋ プロジェクト**)
3. **未完了一覧**: プロジェクトごとの折りたたみグループ

一覧の決まり:

- 既定は**折りたたみ**。開閉状態はブラウザに保存する
- グループの並びは**プロジェクトの並び順**
- **プロジェクト未設定のタスクは「未分類」として一番下**。トップでは**該当が 0 件でも出す**
  —— 放り込み先であり、ドラッグで紐づけを外す落とし先でもあるため
- **タスクが 0 件のプロジェクトも並べる**(そこへ放り込む導線になるため)。
  例外はアーカイブ済みで、こちらはトップに出さない
- 一覧の一番下の左に「完了したタスク →」、右に「アーカイブしたプロジェクト →」

---

## 3. 完了したタスク(`/done`)

- 導線はトップ左下のリンクのみ
- **見え方はトップの未完了一覧と同じ**(プロジェクトごとに折りたたみ、未分類は末尾)。
  ただし並び替えとプロジェクト編集は持たない
- 完了タスクを持つプロジェクトだけ出す(「放り込み先」の意味が無いため 0 件は出さない)。
  未分類グループも 0 件なら出さない —— トップと違うのはここだけ
- カードの「未完了に戻す」でトップへ戻る

## 4. アーカイブしたプロジェクト(`/archived`)

- 導線はトップ右下のリンクのみ。**アーカイブを戻せる唯一の口**
- 見え方はトップと同じ。ここからアーカイブ解除と削除を行う

## 5. ルール(`/rules`)

- 全 Claude Code 環境に効かせたい決まりごとを Markdown で何本でも持つ
- 「まとめて表示」で、有効なルールを**表示順に 1 本へ連結**して表示・コピーできる
  (長押しドラッグの並び順がそのまま連結順)。モーダルは Markdown を素のまま `<pre>` で出し、
  上に貼り先の説明を添える
- 連結の**先頭には 2 つが自動で付く**(ルールとして登録はしない):
  適用範囲の前置き(「特定リポジトリの説明ではなく、作業対象のすべてのリポジトリに効く共通ルール」)と、
  「規約リポジトリ自体は配布専用なので自動更新しない」というルール
- 無効にしたルールは連結に含めない(消さずに一時的に外せる)
- 一覧の下で **規約リポジトリ**(GitHub の `owner/repo` か URL)を設定できる。
  設定すると ✳ ハンドオフの `repositories` に**常に**付与され、そのリポジトリの
  ルート直下 `CLAUDE.md` が読み込まれる。空にして保存すると解除
- 貼り先と運用は [README](../README.md#ルールを-claude-code-に効かせる) 参照

## 6. タスクの操作

### 状態

**未完了 / 完了 の 2 つだけ**。切り替えは**カードのボタンからだけ**行う
(未完了一覧では「完了」、完了一覧では「未完了に戻す」)。
編集モーダルに状態の選択は置かない —— 同じことが 2 箇所からできると、どちらが正か分からなくなるため。

### カード

| 場所 | 操作 |
|---|---|
| 本文 | 押すと**編集モーダル**が開く |
| 右上 📋 | 本文をクリップボードへコピー |
| 📋 の隣 ✳ | **Claude Code へのハンドオフ**(§9) |
| 右下 | 完了 / 未完了に戻す |

### 編集モーダル

- 編集できるのは **タスク内容 / プロジェクト** のみ
- プロジェクトで「プロジェクトなし」を選べば紐づけを外せる
- **物理削除はここから**。誤タップを避けるため一覧には置かない

### プロジェクト紐づけ

任意。未紐づけのまま放り込み、あとから紐づけられる。

## 7. プロジェクトの作成・編集・アーカイブ・削除

**すべてトップで完結する**(専用画面は持たない)。

| 操作 | 場所 | 条件 |
|---|---|---|
| 新規 | 「未完了」見出しの右端の「＋ プロジェクト」 | — |
| 編集 | 各グループ見出しの右端の「編集」 | — |
| アーカイブ | 編集モーダルの右上のボタン | **未完了が 0 件のときだけ** |
| アーカイブから戻す | 同上(アーカイブ済みなら表示が変わる) | 無条件 |
| 削除 | 同じ行の右端の「削除」 | **アーカイブ済みのときだけ** |

- アーカイブのボタンを押すと、**入力中の内容ごと**保存して閉じる(編集を捨てさせない)
- アーカイブを未完了 0 件に限るのは、片付いていないタスクごとトップから消えると
  放り込んだものを取りこぼすため。UI で disabled にするだけでなくサーバー側でも弾く
- 削除は**完了したものを含め、紐づくタスクも一緒に消える(戻せない)**。
  アーカイブ自体が「未完了 0 件」を条件にしているので、片付いたことを確かめる一段を必ず通る

## 8. 並び替えとドラッグ移動

### 並び替え

行のどこでも **長押し(ロングタップ)してからドラッグ**(マウス・タッチ両対応)。
掴み代(☰)は置かない —— 画面が狭く、カード幅を削りたくないため。

| 掴むもの | 変わる並び |
|---|---|
| グループ見出し | プロジェクトの並び |
| カード | そのプロジェクト内のタスクの並び |

- 長押しの前に指を動かせば普通のスクロールのまま(一覧の操作を邪魔しない)
- タスクの手動並び順は**プロジェクト内でだけ**効く。プロジェクトをまたぐ並びは作成日時降順のまま
- 新しく放り込んだタスクはグループの**先頭**に積まれる

### プロジェクト間の移動

カードを**別のプロジェクトのグループまで運んで離すと、そのプロジェクトへ移る**。

- 受け皿になっているグループには枠が付く
- **落とした位置にそのまま入る**
- 「未分類」のグループへ運べば紐づけを外せる。トップでは未分類を 0 件でも出すので、
  **落とす先は常にある**(編集モーダルで「プロジェクトなし」を選んでも同じ)

## 9. Claude Code へのハンドオフ(✳)

タスク内容をプリフィルした `https://claude.ai/code?prompt=…&repositories=…` を新規タブで開く。

- `repositories` には、プロジェクトのリポジトリ URL のうち **GitHub のものだけ**を
  `owner/repo` に変換して渡す。ルール画面で **規約リポジトリ**を設定していれば、
  それも常に加わる(重複すれば足さない)
- 送信はプリフィルのみ。実行開始はその場でワンタップ

### スマホ(iOS)の注意

初期状態ではユニバーサルリンクで Claude アプリが開き、**アプリはクエリのプリフィルを
引き継がないため内容が失われる**(空タブ + JS 遷移、中継ページ経由の JS 遷移のどちらでも回避できなかった)。

- **一度リンクを長押しして「Safari で開く」を選ぶ**と iOS がそれを覚えてブラウザで開くようになり、
  以後はプリフィルが効く
- ホーム画面追加(PWA)の場合はアプリ内ブラウザだと claude.ai のログインセッションを共有しないため、
  `x-safari-` スキームで Safari 本体を開いている

この iOS 依存を減らす将来構想は [README](../README.md#将来構想) 参照。

## 10. 全画面共通

- **下に引っ張って再読み込み**(PWA にはリロード手段が無いため)。
  トップ・完了・ルール・アーカイブ一覧では**データだけ**を取り直し、
  それ以外の画面ではページ全体をリロードする
- モバイルファースト。入力の摩擦を最小にする(トップで「一言書いて即保存」ができること)
- テーマは明暗の切替をヘッダに持つ
- UI 文言はすべて日本語
