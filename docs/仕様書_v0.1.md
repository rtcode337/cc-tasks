## 1. 概要と目的

Claude Code に依頼したいタスクをメモ・管理するための自分専用 Web アプリ。汎用メモアプリではなく、**「メモの最終目的地が Claude Code のプロンプトである」** ことに特化する。

### コンセプト

- メモは「タスクの待ち行列」。出先でスマホ(PWA)から放り込み、帰宅後に Claude Code で消化する
- アプリ自身が MCP サーバーを持ち、Claude Code から直接タスクを取得・更新できる
- Claude Code が実装中の気づきをタスクに書き戻すことで、セッション引き継ぎメモを自動化する

### 利用者

本人 1 名のみ。ただしアクセス主体は 2 種類ある:

| 主体 | インターフェース | 認証方式 |
|---|---|---|
| 人間(本人) | PWA(ブラウザ/スマホ) | Google OAuth(許可メール 1 件固定) |
| Claude Code | MCP(Streamable HTTP) | 静的 API キー(Bearer) |

## 2. スコープ

### v0.1 に含むもの

- プロジェクト(リポジトリ)単位のタスク管理
- タスクの CRUD と 3 状態のライフサイクル管理
- タスクへの追記専用ノート(タイムライン)
- PWA 対応(ホーム画面追加、アプリシェルのオフラインキャッシュ)

- MCP サーバー(ツール 4 種、API キー認証)

### スコープ外(明示)

- 複数ユーザー対応、ユーザー管理画面
- タスクの優先度・ランク付け(将来検討。§10 参照)
- オフライン時のデータ編集・同期(アプリシェルのキャッシュのみ。データは常にオンライン取得)
- 全文検索
- MCP 側の OAuth(静的キーで十分)
- プッシュ通知

| レイヤ | 技術 | 備考 |
|---|---|---|
| バックエンド | Java 21 + Spring Boot 3.x | 初挑戦スタック |
| MCP | Spring AI MCP Server(WebMVC / Streamable HTTP) | REST と同一アプリに同居 |

## 4. アーキテクチャ

```
[スマホ/ブラウザ PWA]                [Claude Code (CLI / Web版)]
        │ HTTPS                              │ HTTPS
        │ Google OAuth セッション              │ Bearer: API キー
        ▼                                    ▼
┌─────────────── リバースプロキシ (TLS終端) ───────────────┐
│                                                        │
│   ┌────────────── Spring Boot (単一コンテナ) ─────────┐  │
│   │  /            → Vue SPA (static)                │  │
│   │  /api/**      → REST API (要 OAuth セッション)    │  │
│   │  /mcp         → MCP Streamable HTTP (要 API キー) │  │
│   │                                                  │  │
│   │  SQLite (ボリュームマウント: /data/cctasks.db)      │  │
│   └──────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────┘
```

- REST と MCP は同一 Spring Boot アプリ内に同居。サービス層を共有し、コントローラ/ツール定義だけ分ける
- MCP トランスポートは Streamable HTTP のみ(stdio・旧 SSE は対応しない)

## 5. データモデル

方針: 性格の異なるデータはテーブルを厳密に分離する。`tasks` は編集可能、`notes` は追記オンリー(タイムライン)。

### 5.1 DDL(SQLite)

```sql
CREATE TABLE projects (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT    NOT NULL UNIQUE,          -- 表示名 (例: "sample-project")
    repo_url    TEXT,                             -- リポジトリ URL (複数可・改行区切り。Web版CC連携で使用)
    description TEXT,
    archived    INTEGER NOT NULL DEFAULT 0,       -- 0/1
    created_at  TEXT    NOT NULL,                 -- ISO 8601 (UTC)
    updated_at  TEXT    NOT NULL
);

CREATE TABLE tasks (
    id                  INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id          INTEGER NOT NULL REFERENCES projects(id),
    title               TEXT    NOT NULL,
    context             TEXT,                     -- 背景・現状・動機
    acceptance_criteria TEXT,                     -- 受け入れ条件
    out_of_scope        TEXT,                     -- やらないこと
    status              TEXT    NOT NULL DEFAULT 'todo'
                        CHECK (status IN ('todo', 'in_progress', 'done')),
    created_at          TEXT    NOT NULL,
    updated_at          TEXT    NOT NULL
);
CREATE INDEX idx_tasks_project_status ON tasks(project_id, status);

CREATE TABLE notes (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id    INTEGER NOT NULL REFERENCES tasks(id),
    author     TEXT    NOT NULL CHECK (author IN ('human', 'claude_code')),
    body       TEXT    NOT NULL,
    created_at TEXT    NOT NULL
);
CREATE INDEX idx_notes_task ON notes(task_id);
```

### 5.2 タスクのライフサイクル

```
todo ──────────→ in_progress ──────────→ done
(未着手)          (Claude Code に投入済み)   (完了)
```

- 状態遷移に制約は設けない(任意の状態から任意の状態へ変更可。手戻り・やっぱり中止を許容)
- `in_progress` への遷移は主に Claude Code が MCP 経由で行う想定
- 削除は物理削除で可(自分専用のため)。ただし notes はタスク削除時にカスケード削除

### 5.3 notes の運用ルール

- **追記のみ。編集・削除 UI は作らない**(タイムラインとしての信頼性を優先)
- `author = 'claude_code'` のノートがセッション引き継ぎメモとして機能する
- Markdown として保存・表示する

## 6. 認証・セキュリティ

### 6.1 PWA(人間)側: Google OAuth

- Spring Security の `oauth2Login`(Google プロバイダ)を使用
- ログイン成功後、メールアドレスを環境変数 `ALLOWED_EMAIL` と照合。**不一致なら 403 で即拒否**(ユーザーテーブルは作らない)
- セッションはサーバーサイドセッション(Cookie)。`SameSite=Lax`, `Secure`, `HttpOnly`
- `/api/**` はセッション必須。未認証は 401 を返し、フロントがログイン画面へ誘導

### 6.2 MCP(Claude Code)側: 静的 API キー

- `/mcp` へのリクエストは `Authorization: Bearer <APIキー>` を必須とする
- キーは十分長いランダム文字列(32 バイト以上を Base64/hex 化)を 1 個発行し、環境変数 `MCP_API_KEY` で保持
- 照合はサーブレットフィルタで実装(`/mcp` パスのみ対象)。不一致・欠落は 401
- キーはタイミングセーフ比較(`MessageDigest.isEqual` 等)を使用

### 6.3 公開に伴う守り

- 公開パスは `/`(SPA)、`/api/**`、`/mcp`、OAuth コールバックのみ。Actuator 等の管理系エンドポイントは無効化するか外部非公開にする
- ログイン試行・MCP 認証失敗のレート制限(簡易でよい。例: bucket4j でIPあたり毎分 N 回)
- セキュリティヘッダ(CSP、X-Content-Type-Options 等)を付与
- リバースプロキシ側での TLS 終端を前提とし、`ForwardedHeaderFilter` を有効化して正しいスキーム/ホストで OAuth リダイレクトが動くようにする

## 7. インターフェース仕様

### 7.1 REST API(PWA 用)

すべて `/api` 配下、JSON、要セッション。

| メソッド | パス | 説明 |
|---|---|---|
| GET | /api/me | ログイン中ユーザー情報(表示用) |
| GET | /api/projects | プロジェクト一覧(`?archived=false` デフォルト) |
| POST | /api/projects | プロジェクト作成 |
| PATCH | /api/projects/{id} | プロジェクト更新(name, repo_urls, description, archived)。repo_urls は配列(空配列で全消し) |
| GET | /api/tasks | タスク一覧。`?projectId=&status=` で絞り込み |
| POST | /api/tasks | タスク作成 |
| GET | /api/tasks/{id} | タスク詳細(notes 込み) |
| PATCH | /api/tasks/{id} | タスク更新(title, context, acceptance_criteria, out_of_scope, status) |
| DELETE | /api/tasks/{id} | タスク削除(notes カスケード) |
| POST | /api/tasks/{id}/notes | ノート追記(author は 'human' 固定) |

エラーレスポンスは `{ "error": { "code": "...", "message": "..." } }` の形式で統一。

### 7.2 MCP ツール(Claude Code 用)

エンドポイント: `POST /mcp`(Streamable HTTP)。Spring AI の `@Tool` アノテーションでサービス層メソッドを公開する。

#### `list_tasks`

- 説明: プロジェクトのタスク一覧を取得する
- 引数: `project`(string, 必須, プロジェクト name)、`status`(string, 任意, todo/in_progress/done。省略時は done 以外)
- 返却: タスクの id / title / status / updated_at の一覧

#### `get_task`

- 説明: タスク詳細を、そのままプロンプトとして使える Markdown で取得する
- 引数: `task_id`(int, 必須)
- 返却例:

```markdown
# タスク #12: タスクに優先度を付けられるようにする

## コンテキスト
(context フィールドの内容)

## 受け入れ条件
(acceptance_criteria フィールドの内容)

## スコープ外
(out_of_scope フィールドの内容)

## これまでの経緯(notes 新しい順)
- [2026-07-20 claude_code] ○○まで実装済み。残: △△
- [2026-07-19 human] そもそもの発端は…
```

#### `update_task_status`

- 説明: タスクの状態を変更する(着手時に in_progress、完了時に done)
- 引数: `task_id`(int, 必須)、`status`(string, 必須)
- 返却: 更新後のタスク概要

#### `add_note`

- 説明: 実装中の気づき・進捗・引き継ぎ事項をタスクに書き戻す
- 引数: `task_id`(int, 必須)、`body`(string, 必須, Markdown 可)
- 挙動: `author = 'claude_code'` で notes に追記
- 返却: 追記したノートの id と created_at

**ツール説明文(description)は Claude Code が自律的に使い方を判断する材料になるため、上記の日本語説明を丁寧に書くこと。** 特に `add_note` には「セッション終了前に、次のセッションが続きから始められる粒度で進捗を書き戻すこと」という利用ガイドを含める。

### 7.3 Claude Code 側の設定

リポジトリ直下の `.mcp.json`(CLI 版・Web 版共通):

```json
{
  "mcpServers": {
    "cc-tasks": {
      "type": "http",
      "url": "https://<公開ドメイン>/mcp",
      "headers": {
        "Authorization": "Bearer ${CC_TASKS_API_KEY}"
      }
    }
  }
}
```

- CLI 版: シェルの環境変数 `CC_TASKS_API_KEY` で展開
- Web 版: サンドボックスの環境変数設定に `CC_TASKS_API_KEY` を登録し、ネットワークアクセスを許可する
- **注意**: Web 版サンドボックスは「フルネットワーク」設定でも外部通信がブロックされる事例が報告されている。Web 版からの疎通は §11 のマイルストーンで実地検証とし、仕様上は「動作見込み・要検証」の扱いとする。CLI 版からの疎通が確実なフォールバック

## 8. フロントエンド(PWA)仕様

### 画面構成(最小)

1. **ログイン画面**: 「Google でログイン」ボタンのみ
2. **タスク一覧(ホーム)**: プロジェクトで絞り込み。status ごとのセクション表示(todo / in_progress / done)。+ ボタンで新規作成
3. **タスク作成/編集**: title(必須)、project(選択)、context / acceptance_criteria / out_of_scope(いずれも Markdown テキストエリア)
4. **タスク詳細**: 本体表示 + notes タイムライン + ノート追記フォーム + status 変更
5. **プロジェクト管理**: 一覧・作成・編集・アーカイブ(モーダルで可)

### UI 方針

- モバイルファースト(主用途は出先のスマホ入力)
- 入力の摩擦を最小に: ホームの + から「title だけ入れて即保存」ができること。詳細フィールドは後から埋められる
- 状態管理は Pinia、ルーティングは Vue Router。UI ライブラリは任意(素の CSS でも可、実装時に判断)

### PWA 要件

- vite-plugin-pwa で manifest(name, icons, `display: standalone`)と Service Worker を生成
- キャッシュ戦略: アプリシェル(JS/CSS/フォント)は precache。`/api/**` は **network-only**(データの陳腐化防止。オフライン対応はスコープ外)
- オフライン時はエラーバナー表示のみ(入力データの退避は将来検討)

## 9. 非機能要件・運用

- **メモリ制約**: 本番サーバーは非力なため、JVM は `-XX:MaxRAMPercentage` 指定または `-Xmx256m` 程度を目安に調整。起動時間・フットプリント確認を M1 の完了条件に含める
- ベースイメージは JRE 系の軽量イメージ(例: `eclipse-temurin:21-jre-alpine` 相当)
- SQLite ファイルは `/data/cctasks.db` にボリュームマウント。バックアップはファイルコピーで可(cron 等はアプリ外の責務)
- ログは stdout に JSON または plain で出力(`docker logs` で追える形)
- 環境変数一覧:

| 変数 | 用途 |
|---|---|
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Google OAuth クレデンシャル |
| `ALLOWED_EMAIL` | ログインを許可する Google アカウントのメール(1 件) |
| `MCP_API_KEY` | MCP 用静的 API キー |
| `DB_PATH` | SQLite ファイルパス(デフォルト `/data/cctasks.db`) |
| `PUBLIC_BASE_URL` | 公開 URL(OAuth リダイレクト構築用) |

### Claude Code への実装指示メモ

- 実装は M1 から順に。各マイルストーン完了時に動作確認手順を CLAUDE.md か PR 説明に残すこと
